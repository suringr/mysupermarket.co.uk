# MySupermarket

**Live tracking of UK food prices, inflation trends, and safety alerts — no predictions, just official data.**

MySupermarket uses a NextReset-style static site architecture with Last-Known-Good (LKG) data vault for resilient data refresh.

## Architecture Overview

- **Static Route HTML**: Real `index.html` files for SEO (/, /price-pressure/, /inflation-trends/, /alerts-recalls/)
- **SPA Hydration**: Same JavaScript bundle loads on all routes, detects path, and hydrates
- **JSON Data**: Pure data files in `public/data/` with status semantics (`fresh`, `stale`, `unavailable`)
- **LKG Vault**: Last-known-good data stored in `public/data/_lkg/`, used as fallback when providers fail

## Local Development

```bash
# Install dependencies
npm ci

# Refresh data from providers
npm run refresh:data

# Build site (client + routes + export)
npm run build

# Start local server
npm start
```

Visit http://localhost:3000

## Key Folders

| Path | Purpose |
|------|---------|
| `public/data/` | Live data (overwritten every refresh) |
| `public/data/_lkg/` | LKG vault (only written on fresh status) |
| `public/data/_debug/` | Debug artifacts (optional snapshots, excluded from dist) |
| `public/<route>/index.html` | Static route shells (generated by `generate:routes`) |
| `dist/` | Published output (copied from public/) |
| `src/shared/routes.ts` | Single source of truth for routes (prevents drift) |

## Status Semantics

| Status | Meaning |
|--------|---------|
| `fresh` | Fetched successfully this run |
| `stale` | LKG reused (provider failed, fallback active) |
| `unavailable` | Provider failed and no LKG available |

## Scripts

| Command | Description |
|---------|-------------|
| `npm run refresh:data` | Fetch data from providers, write to `public/data/`, auto-generate registry |
| `npm run build:client` | Bundle `src/client/app.ts` → `public/assets/app.js` (esbuild) |
| `npm run generate:routes` | Generate static HTML route pages from template |
| `npm run export:site` | Copy `public/` → `dist/` (excludes `_debug/`) |
| `npm run build` | Full build: client + routes + export |
| `npm start` | Serve `dist/` locally |

## Adding a New Provider

1. **Create provider file**: `scripts/providers/uk.<name>.ts`

```typescript
import { ProviderOutput } from "../lib/types";

const META = {
    provider_id: "uk.example",
    title: "Example Provider",
    type: "price-pressure", // or "inflation-trends" or "alerts-recalls"
    source_url: "https://example.gov.uk/data"
};

export async function run(): Promise<ProviderOutput> {
    // Fetch and parse data
    // On success: return { ...META, status: "fresh", ... }
    // On failure: throw new Error("reason")
}
```

2. **Register provider** in `scripts/refresh-data.ts` PROVIDERS array
3. **Run** `npm run refresh:data` and verify outputs in `public/data/`

## Adding a New Route

See **[docs/ADDING_PAGES.md](docs/ADDING_PAGES.md)** for step-by-step instructions.

Quick summary:
1. Add route to `src/shared/routes.ts`
2. Add route handler in `src/client/app.ts`
3. Run `npm run generate:routes && npm run build`
4. Verify `dist/<route>/index.html` exists

## Data Refresh Behavior

- **Default (fail-safe)**: Exit code 1 if ≥50% of providers unavailable
- **Strict mode**: Set `STRICT_REFRESH=true` to exit code 1 if *any* provider unavailable

## Deployment

Deploy the `dist/` folder to any static host (Cloudflare Pages, GitHub Pages, Vercel, Netlify).

**Cloudflare Pages:**
- Build command: `npm run build`
- Output directory: `dist`
- Node.js: v18+
